## DIREÇÃO ARQUITETURAL OBRIGATÓRIA

O cadastro novo não deve usar uma lista universal de perguntas fixas. Três
entradas devem convergir para um contrato estruturado comum:

```text
entrada manual
      \
JSON -----> contrato de cadastro -> validação -> API de conhecimento -> linguagem.db
      /
IA/professor
```

Regras:

- o professor não escreve diretamente no SQLite;
- o professor não escolhe tabela ou coluna física;
- o mapeamento para `linguagem.db` fica no código Python/API de conhecimento;
- o JSON é proposta/entrada estruturada, nunca código executável;
- o sistema funciona sem IA;
- IA, internet e professor são fontes de proposta, não aprovadores;
- toda proposta preserva fonte, evidência, incerteza e estado de autorização;
- informação fornecida, proposta e confirmada permanecem diferenciadas;
- o mecanismo antigo só será removido depois de substituição testada;
- não criar microfases para cada detalhe da arquitetura.

Infraestrutura a preservar:

- `professor/professor.py` — abstração, comunicação, histórico, cache e erros;
- `professor/professor_llama.py` — adaptador local via Ollama.

Papéis futuros do professor:

1. **Respondente:** responde uma pergunta específica.
2. **Estruturador:** propõe a estrutura necessária para cadastrar uma entrada,
   sem inventar dados ausentes e registrando incertezas.

O cadastro manual poderá ser uma entrevista dinâmica: identificar o objeto,
consultar o que já existe, detectar lacunas, fazer a próxima pergunta
necessária, validar a resposta, atualizar a proposta e pedir autorização antes
da persistência. A coordenação permanece no HEN-ISANA.
